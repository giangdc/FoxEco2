### Step 4: Generate / Update Page Object

#### Page Object template (TypeScript Playwright):

```typescript
import { Page, Locator, expect } from '@playwright/test';
import { BasePage } from './BasePage';

/**
 * LoginPage — Page Object cho login form.
 * Generated by /implement-automation từ TC-MASTER on YYYY-MM-DD.
 *
 * Implements Req: REQ-01, REQ-02, ...
 */
export class LoginPage extends BasePage {
  // ===== Locators (initialized in constructor) =====
  private readonly email: Locator;
  private readonly password: Locator;
  private readonly submitButton: Locator;
  private readonly rememberMeCheckbox: Locator;
  private readonly errorMessage: Locator;
  private readonly forgotPasswordLink: Locator;

  constructor(page: Page) {
    super(page);
    this.email = page.getByLabel('Email');
    this.password = page.getByLabel('Password');
    this.submitButton = page.getByRole('button', { name: 'Đăng nhập' });
    this.rememberMeCheckbox = page.getByLabel('Remember me');
    this.errorMessage = page.locator('.error-message');
    this.forgotPasswordLink = page.getByRole('link', { name: 'Quên mật khẩu' });
  }

  // ===== Action methods (verb-target naming) =====

  /**
   * Navigate to login page.
   */
  async navigate(): Promise<void> {
    await this.goto('/login');
  }

  /**
   * Enter email value.
   * @param value Email string
   */
  async enterEmail(value: string): Promise<void> {
    await this.email.fill(value);
  }

  /**
   * Enter password value.
   * @param value Password string
   */
  async enterPassword(value: string): Promise<void> {
    await this.password.fill(value);
  }

  /**
   * Toggle Remember Me checkbox.
   */
  async toggleRememberMe(): Promise<void> {
    await this.rememberMeCheckbox.click();
  }

  /**
   * Submit login form.
   */
  async clickSubmit(): Promise<void> {
    await this.submitButton.click();
  }

  /**
   * Combined helper: enter credentials + submit.
   */
  async login(email: string, password: string): Promise<void> {
    await this.enterEmail(email);
    await this.enterPassword(password);
    await this.clickSubmit();
  }

  // ===== Getter methods (return Promise<value>) =====

  /**
   * Get error message text.
   * @returns Error message text or empty string nếu element không visible
   */
  async getErrorMessage(): Promise<string> {
    if (!(await this.errorMessage.isVisible())) return '';
    return (await this.errorMessage.textContent()) || '';
  }

  /**
   * Check if error visible.
   */
  async isErrorVisible(): Promise<boolean> {
    return await this.errorMessage.isVisible();
  }

  /**
   * Check if submit button enabled.
   */
  async isSubmitEnabled(): Promise<boolean> {
    return await this.submitButton.isEnabled();
  }
}
```

#### Rules

- **One class per page**, file name `<Name>Page.ts`
- **Locators are `private readonly Locator`**, initialized in constructor
- **Action methods async/await**, return `Promise<void>` unless return value needed
- **Getter methods**: name starts với `get`/`is`/`has`, return `Promise<string|boolean|number>`
- **No business logic** — just element interaction (logic stays in tests)
- **Strict null checks** — handle missing/optional elements explicitly
- **JSDoc comments** cho public methods (preserved khi update class)
- **Imports order:** Playwright API → BasePage → other Page Objects → utils

### Step 5: Generate / Update Test Spec

#### Test spec template

```typescript
import { test, expect } from '@playwright/test';
import { LoginPage } from '../pages/LoginPage';

/**
 * Test spec for REQ-01..NNN.
 * Generated by /implement-automation từ TC-MASTER on YYYY-MM-DD.
 */

test.describe('REQ-01 — User authentication', () => {
  let loginPage: LoginPage;

  test.beforeEach(async ({ page }) => {
    loginPage = new LoginPage(page);
    await loginPage.navigate();
  });

  test('TC_01.1: Happy path / REQ-01', async ({ page }) => {
    // Pre-condition: User has valid account (per TC-MASTER column G)

    // Step 1: Nhập email hợp lệ
    await loginPage.enterEmail(process.env.TEST_USERNAME!);

    // Step 2: Nhập password
    await loginPage.enterPassword(process.env.TEST_PASSWORD!);

    // Step 3: Click button Đăng nhập
    await loginPage.clickSubmit();

    // Expected 1: Redirect to /dashboard
    await expect(page).toHaveURL(/dashboard/);

    // Expected 2: Username displayed in header
    await expect(page.locator('.user-greeting')).toContainText(process.env.TEST_USERNAME!);
  });

  test('TC_01.2: Invalid email format / REQ-02', async ({ page }) => {
    // Step 1: Nhập email sai format
    await loginPage.enterEmail('not-an-email');

    // Step 2: Nhập password valid
    await loginPage.enterPassword('Password123');

    // Step 3: Click submit
    await loginPage.clickSubmit();

    // Expected 1: Error message displayed
    await expect(loginPage.isErrorVisible()).resolves.toBe(true);

    // Expected 2: Error text matches spec
    await expect(loginPage.getErrorMessage()).resolves.toContain('Email không hợp lệ');
  });
});
```

#### Rules

- **`test.describe` block per Req ID (hoặc per module nếu 1 Req ID trải nhiều TC không liên quan)** — group related TCs
- **Describe name:** `'[Req ID] — <feature name>'` (vd `'REQ-01 — User authentication'`) — template ISC không còn Scenario ID column, dùng Req ID (cột B) làm khoá nhóm
- **Test name MUST follow pattern:** `'[TC ID]: <title> / [Req ID]'` (vd `'TC_01.1: Happy path / REQ-01'`; optional `/ Technique: <tag>` cho comprehensive mode). TC ID lấy nguyên giá trị cột A đã resolve — KHÔNG tự đặt/đoán chuỗi semantic
- **`test.beforeEach`** cho common setup (navigate, login, etc.)
- **`// Step N:` comments** mapping 1:1 với TC-MASTER **column H** (Test Steps)
- **`// Expected N:` comments** mapping 1:1 với TC-MASTER **column I** (Expected Result)
- **All await assertions** (forget await = silently no-op)
- **Env vars với `!` non-null assertion** hoặc fallback default
- **Use Page Object methods** — NO inline `page.locator(...)` calls (KHÔNG bypass POM)

## Comprehensive mode — DataProvider equivalent (TypeScript)

Khi Version MEMORY §9 (TC Gen Log) Mode = `comprehensive` HOẶC `selective`, derived TCs từ techniques (B1 EP, B2 BVA, B6 EG) thường có pattern lặp lại. **Use loop pattern** (analog to Java `@DataProvider`):

### Pattern A: Inline data array + for...of loop

```typescript
import { test, expect } from '@playwright/test';
import { LoginPage } from '../pages/LoginPage';

const passwordBoundary = [
  { length: 7,  expected: false, tcId: 'TC_03.14', technique: 'BVA-min-1' },
  { length: 8,  expected: true,  tcId: 'TC_03.15', technique: 'BVA-min' },
  { length: 9,  expected: true,  tcId: 'TC_03.16', technique: 'BVA-min+1' },
  { length: 31, expected: true,  tcId: 'TC_03.17', technique: 'BVA-max-1' },
  { length: 32, expected: true,  tcId: 'TC_03.18', technique: 'BVA-max' },
  { length: 33, expected: false, tcId: 'TC_03.19', technique: 'BVA-max+1' },
  { length: 0,  expected: false, tcId: 'TC_03.20', technique: 'BVA-empty' },
];

test.describe('REQ-08 — Password length boundary (BVA suite)', () => {
  let loginPage: LoginPage;

  test.beforeEach(async ({ page }) => {
    loginPage = new LoginPage(page);
    await loginPage.navigate();
  });

  for (const data of passwordBoundary) {
    test(`${data.tcId}: length ${data.length} → ${data.expected ? 'accept' : 'reject'} / REQ-08 / Technique: ${data.technique}`, async ({ page }) => {
      // Step 1: Enter email (valid)
      await loginPage.enterEmail('user@example.com');

      // Step 2: Enter password với length per data row
      await loginPage.enterPassword('p'.repeat(data.length));

      // Step 3: Click submit
      await loginPage.clickSubmit();

      // Expected: based on data.expected
      if (data.expected) {
        await expect(page).toHaveURL(/dashboard/);
      } else {
        await expect(loginPage.isErrorVisible()).resolves.toBe(true);
      }
    });
  }
});
```

## Common Edge Cases

### Element not found trên page

Khi locator extracted từ MCP nhưng KHÔNG match thật:
```
"Locator 'button[data-testid=login]' không match element trên page hiện tại.
 URL: <url>. Re-snapshot via Playwright MCP?"
→ User confirm → re-extract locator → regenerate
```

### Multiple matching elements (strict mode violation)

Playwright strict mode default — locator must match exactly 1 element:

```typescript
// ❌ Error: strict mode violation — 3 elements match
await page.locator('button').click();
```

→ Refine locator với:
- `getByRole('button', { name: 'Submit' })` — by accessible name
- `locator('button').filter({ hasText: 'Submit' })` — chain filter
- `locator('button').first()` — nếu chấp nhận first

Document choice trong comment: `// Specify name to avoid strict mode collision`.

### Page load chậm / Dynamic content

```typescript
// Wait for specific element before action
await page.waitForLoadState('networkidle');
await this.waitForVisible(this.submitButton, 30_000);
await this.submitButton.click();
```

### Authentication required

Cho protected routes, use **storage state** (auth state captured globally):

```typescript
// In playwright.config.ts
use: {
  storageState: 'storage-state.json',
},

// Or in fixture
const authenticatedPage = test.extend({
  context: async ({ browser }, use) => {
    const context = await browser.newContext({ storageState: 'auth.json' });
    await use(context);
  },
});
```

`init-source-code` scaffold setup.ts có boilerplate cho pattern này.

### Toast/notification race condition

```typescript
// ❌ Bad: race condition — toast disappears before assertion
await page.locator('button').click();
await expect(page.locator('.toast')).toBeVisible();  // may fail if toast already gone

// ✅ Good: wait for toast immediately after action
await Promise.all([
  page.locator('.toast').waitFor({ state: 'visible' }),
  page.locator('button').click(),
]);
```

### File upload

```typescript
// Set file directly (no real file open dialog)
await page.locator('input[type=file]').setInputFiles('path/to/file.pdf');
```

### Download

```typescript
const downloadPromise = page.waitForEvent('download');
await page.locator('a.download-link').click();
const download = await downloadPromise;
await download.saveAs('downloads/' + download.suggestedFilename());
```

### iframe handling

```typescript
const frame = page.frameLocator('iframe#payment-form');
await frame.locator('#card-number').fill('4111111111111111');
```

### MCP locator extraction edge cases

- **Shadow DOM elements:** Playwright pierces shadow DOM by default. Use `>>` chain for nested: `page.locator('host >> shadow-element')`.
- **Dynamic IDs (vd Angular):** Use `getByRole` + `name` instead of `#auto-gen-id`.
- **i18n text:** Use language-neutral selectors (testid, role, aria-label) thay vì hardcoded text khi possible.

## TypeScript-specific lints/best practices

### Strict mode TypeScript

`tsconfig.json` có `"strict": true` — enforce:
- No implicit `any`
- Strict null checks (`X | undefined` must be handled)
- Function return type explicit (recommend)

### ESLint rules (recommended)


### Common pitfalls (catch in review)

| Pitfall | Symptom | Fix |
|---|---|---|
| Missing `await` on assertion | Test passes silently when shouldn't | Always `await expect(...)` |
| `process.env.X` without `!` or default | TypeScript error trong strict mode | `process.env.X!` or `process.env.X ?? 'default'` |
| `if/else` in test instead of data table | Hard to debug, untraceable | Refactor to `for (const data of [...])` loop |
| Inline locator in test (bypass POM) | Coupling, hard maintain | Move to Page Object class |
| `page.waitForTimeout(5000)` | Brittle, slow | Use `waitForLoadState`, `waitFor`, or `expect.toHaveText` polling |
| Mixing CSS + XPath without prefix | Locator strategy unclear | Use Playwright builders (`getByRole`, `getByLabel`) preferred |
